# PicoMarQ — version history and design notes

This was the README of the builds before PicoMarQ was published. It records what each version changed and why things are built the way they are. The `changes-since-*.patch` files it mentions are in the `history` folder.

A document editor (named Quill in builds 0.1.6–0.1.11) adapted from [Scratch by Eric Li](https://github.com/erictli/scratch), preserving its React/TipTap formatted editor, typography, toolbar, Markdown source mode, tables, math, and diagrams.

This version removes folder navigation, folder settings, AI integrations, Git integrations, the writing-direction setting, and document export. The desktop shell uses Electron so the Windows portable build contains its runtime and needs no external toolchain.

## Use

Extract the Windows ZIP completely and run **PicoMarQ.exe**. Windows 10/11 x64. The build is not code-signed. PicoMarQ is independent of upstream Scratch.

- PicoMarQ uses one independent native window per document. File, Edit, View, and Help keep their compact row; the document-switching list has been removed from View. Windows can be placed side by side or on separate monitors, with normal clipboard operations between them.
- Version 1.3.4 changes the engine and nothing else: Electron 44.11.5 (Chromium 152.0.7977.169, Node.js 24.22.3) in place of 44.6.0 (Chromium 152.0.7977.130), the same generation of Chromium with the fixes published in between. The compiled program in `dist/` and the main-process files in `desktop/` are byte for byte those of 1.3.3. Every file of the runtime is new, so the Windows package is built from Electron's official package instead of from the previous release. One test was corrected: `tests/desktop-smoke.cjs` waits for the focus before it presses Ctrl+W (see the note on shortcuts under Close Window below).
- Version 1.3.3 mends five things found in a review of 1.3.2. Undo stops at the text a document was opened with (it could take the whole text out, and a save then wrote an empty file). Red lines in long paragraphs survive typing with Smart Typography, and come back by themselves, without the others blinking, after Bold, Italic, Undo or Enter. Find treats a typed apostrophe, quotation mark, two hyphens and three periods as also meaning their typeset forms, and finds a phrase across a change of formatting; Replace typesets its text when Smart Typography is on. Replace All replaces every match, not the first 500. And a picture whose address points at another computer's shared folder is not loaded.
- Version 1.3.2 makes Find and Replace get along with the spelling checker. Find's highlights no longer take the red lines away from the paragraphs that contain a match (through 1.3.1 they did, and the lines stayed away after Find was closed); the highlights look the same. Text put in by Replace and Replace All is spell-checked when the caret returns to the document, with the usual second without red lines. And the recheck that follows a paste, Ignore All or Clear Custom Dictionary no longer waits for the mouse to move, which it sometimes did while text was selected.
- Version 1.3.1 adds Ignore All, Clear Custom Dictionary, and About. **Ignore All** is in the right-click menu of a word the spelling checker has marked, above Add to Dictionary: every occurrence of that word in the document loses its red line, including occurrences typed later, until the document is closed or PicoMarQ exits. Nothing is written into the Markdown file or the dictionary. The other red lines disappear for about a second and come back, as after a paste. **Settings > Spelling > Clear Custom Dictionary…** removes every word added with Add to Dictionary, after a question that lists the words and has Cancel as its default; the words are then marked as misspelled again in every open document. **Help > About PicoMarQ** (a fourth menu, Alt+H) shows the version and that PicoMarQ is based on Scratch by Eric Li, with buttons that open the two projects' pages on GitHub. A personal name, a university and an address in the test document, the tests, the icon notes and the oldest patch file were replaced with placeholders.
- Version 1.3.0 shows the selected words in the status bar: with text selected, the word count reads "56 of 1,234 words" (words in the selection, then the document's total); with nothing selected it reads "1,234 words" as before. It follows the selection as it changes, with the mouse or the keyboard, in both views, for selected table cells, and for the match that Find selects in Markdown source. Selecting everything gives the document's count. A partly selected word counts as a word; a selected image, horizontal rule, or empty line shows no selected count, because no text is selected; selected text without words (a space, a period) shows 0. Settings > Typography now labels the size box **Point Size (12-24)**; the box itself works as in 1.2.7.
- Version 1.2.7 fixes three things. Spell checking now covers opened files and pasted text, not only what you type, and always uses US English. Settings > Size (and Custom Width) accept typed numbers: a size from 12 to 24 takes effect as you type it, and anything outside the range moves to the nearest limit when you press Enter or leave the box; the arrow keys still step it. Settings > Saved Themes adds Restore Default Theme…, which, after asking, returns colors (Light and Dark), typography, and User Interface settings to their defaults, keeping Light or Dark, Startup, and Smart Typography as they are.
- Version 1.2.6 adds Save Theme… and Load Theme… under Settings > Saved Themes. Themes are portable JSON files in a Themes folder beside PicoMarQ.exe (or any location you select in the Windows dialog). They contain light/dark appearance and both color palettes, typography, page width, text zoom, and formatting icon size; no Markdown, startup choice, or smart-typing behavior is stored. Missing installed fonts fall back to Sans. Heading 4 is now bold, without changing its size. This release is based directly on 1.2.4 and retains its original hex color picker, deliberately omitting the 1.2.5 picker changes.
- Version 1.2.4 displays blockquotes in regular text with their existing gray left rule and no automatic quotation marks; explicitly italicized words inside quotations remain italic. Settings > Theme > Customize colors now has separate Text and UI groups, with six additional per-theme colors for Headings 1–4, Bold, and Italic. Normal paragraph text and those six categories default to black in light mode and white in dark mode. Colors are display-only preferences, not Markdown document formatting.
- Version 1.2.3 makes File > Close Window and Ctrl+W leave a fresh blank document when closing the last document. The replacement keeps the same size, position and maximized state. Save/Discard/Cancel still applies, and a canceled Save As retains the original draft. With several windows, Close Window closes only the selected one. Repeatedly closing the blank document keeps the app open.
- Version 1.2.2 fixes restoration after using the title-bar close button or Alt+F4 on the final window. These use the same session-preserving exit as File > Exit. Closing immediately after a file launch waits for startup to finish; rapid window closes are processed in order so the final document is retained.
- Version 1.2.1 places Startup at the bottom of Settings, below User Interface.
- Version 1.2.0 adds Settings > Startup > When PicoMarQ starts: Restore previous session (the default for existing profiles) or Start new session. The choice applies at the next launch, is remembered in AppData on each machine, and keeps preferences and recent files. New-session startup opens one blank document, or the file supplied by Windows when launched through a file association.
- Restore mode continues automatic draft recovery. In New mode, unsaved recovery snapshots trigger a Restore Session / Start New Session prompt before any previous documents are cleared. Restore is the default and the Escape/close action; explicitly choosing New discards the recovered edits while leaving saved files untouched.
- File > New creates another window. File > Open, Open Recent, and file-association launches create a window for each selected file. Reopening an already-open file raises its existing window, preserving unsaved edits and avoiding conflicting copies. Open Recent keeps the last four distinct files opened or saved, including after restarting.
- Page width offers Full (the default) or Custom. Custom widths can be set in Settings or adjusted with the page-edge handles; double-click a handle to return to Full.
- Spell checking (US English) covers the whole document: opened files, restored drafts, pasted or dragged-in text, and text edited in Markdown source view are checked as well as what you type. Chromium, the engine inside PicoMarQ, normally checks only text it sees typed, a privacy rule for websites that PicoMarQ turns off at startup (`desktop/main.cjs`) because it shows no websites. After a paste the whole document is rechecked, so other underlines disappear for about a second (a few seconds in very long documents).
- Right-click menus with spelling suggestions: a misspelled word's suggestions, Ignore All (this document, until it is closed) and Add to Dictionary (for good) come first, then Bold and Italic (with their shortcuts; in source view they wrap the selection in `**` or `*`), Cut, Copy, Paste, and the table commands when the cursor is in a table. An existing selection is retained. (The editor registers its items synchronously from the DOM event and lets the browser's own context-menu request through, since only that request carries Chromium's suggestions.)
- Installed font families in Settings, with Refresh fonts.
- Text zoom from 50% to 200% with Ctrl+plus (Ctrl+= or Ctrl+Shift+=), Ctrl+minus, their numeric-keypad equivalents, Ctrl+0, and Ctrl+mouse wheel.
- Menus, formatting icons, Find controls, status bar, and page width stay at their normal size when text zoom changes. Source text zooms too.
- Settings > Icon Size, below Text Zoom, offers 100% (default), 150%, and 200% for formatting toolbar icons only (the Find magnifier among them). Menus, their dropdowns, and document text keep their sizes.
- Markdown source wraps to the available window/page width, including long links and code lines. Wrapping changes only their display; saved Markdown line breaks stay intact. Find and source/view positioning account for wrapped lines.
- The PicoMarQ icon in the window and Windows executable: a white sheet with a folded corner and a bold red outline, carrying the Markdown "M" whose right stem runs down into an arrowhead. It fills the icon square like other app icons, with transparent corners.
- A live word count beside zoom in the status bar. It counts document text in both editing views, excluding Markdown formatting markers and hidden link URLs. While text is selected it reads "x of n words", where x is the number of words in the selection. The settings sample preview has been removed.
- Markdown files are saved manually. Recovery snapshots merge independently for each window, retaining drafts, selection, scroll, source mode, size, position, and maximized state. Preferences remain in the existing AppData profile and changes apply to every open window.
- File > Close Window (Ctrl+W) removes the current document from the session after Save/Discard/Cancel. It closes that window when others remain, or replaces the final document with a blank at the same position when no other window remains. A failed replacement load keeps the original document and recovery data. The title-bar close button and Alt+F4 close the native window; on the last window they exit and retain its saved document for restoration when Restore is selected. Discard during Exit keeps the saved version of a named document and removes an untitled draft.
- The windows share one menu (`buildMenu` and `menuFor` in `desktop/main.cjs`). The command of a menu shortcut runs a moment after the key press, for the window that has the focus then. With a keyboard that is the window the key was pressed in, unless the focus moves in that moment, as it does when a new window appears; a window with unsaved changes asks before it closes whichever window the command reaches. A test that sends a key by program has to wait until its window has the focus: a key sent straight after asking for the focus is faster than the focus, and its command goes to the window that still has it. `tests/desktop-smoke.cjs` waits since 1.3.4.
- File > Exit (Ctrl+Shift+Q) checks all windows and retains the remaining saved documents for the next launch when Restore is selected. Discard choices take effect only after every prompt succeeds; a later Cancel preserves all drafts and windows. Canceling Save As also cancels closing. Unsaved drafts remain available for recovery after an unexpected termination.
- Revert to Saved confirms before rereading the current file from disk in the same window and clearing its undo history. It is disabled for untitled documents. A failed read preserves current text. The Refresh control for external edits uses the same operation.
- Find and Replace stays above the scrolling text in both views until explicitly closed. Each window has independent Find and Undo state.
- Conflict checking before replacing a file that changed elsewhere; Save As preserves both versions.
- Smart typography (Settings > Typography, on by default): two hyphens become an em dash, three periods an ellipsis, and straight quotes become curly quotes as you type, in both views. A third hyphen gives `---` back so horizontal rules, front matter, and table rows can still be typed; code blocks, inline code, math, link addresses, HTML, and front matter are never changed. Backspace in the formatted view or Ctrl+Z in the source view restores what you typed. Edit > Apply Smart Typography converts an existing document in a single undo step and reports how many changes it made.
- Heading 4 is bold like the other headings (italic and regular weight before 1.2.6), sized halfway between Heading 3 and body text.
- Settings groups Page Width, Text Zoom, and Icon Size under User Interface; Typography and User Interface each have their own Reset to defaults.
- `/` is an ordinary character. Scratch's slash-command menu (which opened on `/` at the start of a line and kept Enter until a command matched) is removed; every command it offered remains in the toolbar, the menus, or Markdown syntax.
- Version 0.1.12 renames the app from Quill to PicoMarQ (window title, executable, metadata); 0.1.13 brings the final icon and the capital-Q spelling.
- Version 1.0.1: the right-click menu offers Bold and Italic instead of Undo and Redo, and no longer lists Select All.
- Version 1.0: Save As is F12 (Ctrl+Shift+S was taken by strikethrough in the formatted view, so it never reached Save As there); underline is saved as `<u>…</u>` rather than the toolkit's `++…++`, so other programs read it; Settings > Theme offers Light and Dark only (a profile set to System takes the OS setting once); the Find magnifier moved from the menu row to the right end of the formatting toolbar and scales with the other toolbar icons (in source view, where the toolbar is hidden, Ctrl+F opens Find).
- Backslash escapes work both ways. A file that escapes Markdown punctuation the way Pandoc, Typora, and most other tools do (`\$1,200`, `p \< .05\*`, `chapter\_one`, `1986\.`) shows the plain characters in the formatted view instead of dropping them, and what you type is saved so that it reads back the same: `5 * 3` is written `5 \* 3`, `C:\Users` is written `C:\\Users`, a paragraph beginning `1986.` is written `1986\.` so it stays a paragraph. Text that was never going to be misread is written unchanged; headings, table cells, and code are left alone.

Markdown source is available through View or Ctrl+Shift+M. The toolbar omits inline code, code blocks, block math, wikilink insertion, and Heading 4; Ctrl+E still toggles inline code, and math/wikilink syntax is supported.

Added/pasted images are embedded as data URLs. Existing relative image links resolve against the document's location. Source and code blocks stay monospace. Switching open documents preserves their undo histories. Recovery after a restart does not restore undo history; opening a recovered document starts a new undo history.

The Windows portable distributions from 1.2.4 through 1.3.3 were assembled from the previous release's package: the Electron 44.6.0 x64 runtime was kept byte for byte, the application files in `resources/app` were replaced, and only the version information in the `.exe` was updated (`scripts/repack-windows-from-*.py`; 1.3.3 came from 1.3.2). The 1.2.3 runtime had been packaged from Electron's official release with checksum verification, and 1.3.4, which changes the engine to Electron 44.11.5, is packaged that way again (`npm run package:windows`, below). A later release that keeps the engine can be assembled from the 1.3.4 package as before. Since 1.2.7 the renderer in `dist/` is compiled from this TypeScript source. The app is tested on Linux with the same Electron version; it has not been run on Windows in the build environment. `VALIDATION.md` has the details for this release.

## Performance

Version 0.1.7 makes large documents usable without changing any feature or the Markdown that is saved. On a 2 MB file (about 21,000 lines, 230,000 words) opening went from about 16 s to under 4 s, each keystroke in the formatted view from about 220 ms to about 100 ms, switching to Markdown source from more than a minute to under a second, and each keystroke in source view from several seconds to about 60 ms. On a 500 KB file the same figures are 1.7 s → 1.1 s, 66 ms → 33 ms, 4.3 s → 0.35 s, and 3 s → 26 ms. The main fixes:

- TipTap's ordered-list and task-list Markdown tokenizers split the entire remaining document into lines at every block, which made parsing quadratic. `src/components/editor/markdown-tokenizers.ts` wraps them so they only see the lines a list can span; the tokens they return are identical.
- The live word count re-counted the whole document on every keystroke, and in source view re-parsed the whole document on every keystroke. It now counts per block with a cache keyed by the immutable editor nodes, and in source view runs 300 ms after typing pauses.
- Markdown serialization (used by the 500 ms save and the 1 s recovery timer) is cached per document version and rendered per block (`markdown-serialize.ts`), so an idle editor no longer re-serializes a changed document every second.
- Code highlighting (`lowlight-plugin.ts`) no longer walks the whole document on every transaction or re-highlights every code block when one is edited.
- The formatted editor stays mounted (hidden) while the source view is open instead of being torn down and rebuilt, and the source textarea gets an explicitly resolved text direction instead of `dir="auto"`, which Chromium re-resolves at great cost for multi-megabyte values.
- StarterKit's duplicate Link extension is disabled (the configured Link is the only one), the toolbar re-renders only when an active state changes, recovery snapshots are compared structurally instead of through multi-megabyte `JSON.stringify` calls, the main process no longer deep-copies document text for every menu rebuild, and documents restored in the background are parsed when first shown.

Version 1.3.0's selected-word count is built so that selecting stays as fast as it was:

- `countSelectedWords` (`src/lib/word-count.ts`) gives the same number as counting the selected text from scratch, but blocks whose text lies wholly inside the selection reuse the document count's cached per-block numbers; only a block cut by an end of the selection is counted afresh. With everything selected in a 2 MB document (about 250,000 words) a count takes about 0.2 ms.
- The count is made at most once per frame and written straight into the status bar element (`WordCount` in `src/App.tsx`), not through React state. On every React update React re-reads the caret by walking the focused editor's content, which is slow in a long document, and a dragged selection changes many times a second.
- In Markdown source view the selected text is parsed like the whole source, so markers and link addresses are not counted and selecting everything gives the document's count. A selection up to 20,000 characters (or one already counted, such as everything) is counted on the next frame; a longer one 0.3 s after the selection stops changing. A selection that cuts through Markdown syntax is counted as the text it would be on its own: selecting only a link's address, or only the description inside an image, counts those words although the document count leaves them out.

Version 1.3.1's Ignore All (`src/components/editor/IgnoredSpelling.ts`, `src/lib/ignored-spelling.ts`, `src/lib/spelling.ts`) works around the spelling checker instead of through it:

- Chromium has no way to ignore a word except adding it to the dictionary, which is for good (and on Windows may also put the word into the system's own dictionary). It does leave a word unmarked when the word starts inside an element that has spell checking switched off, so a decoration wraps the first letter of every occurrence in such an element. The document and its Markdown are not changed, and each window keeps the list for its open document in memory only.
- Only the first letter is wrapped, because Chromium runs its background checks only while the caret is at a place where spell checking is on. The caret can be "inside" a one-letter wrapper only at its two edges, and there the selection is rewritten to name the same place from the neighboring text. The checks never stop, and the arrow keys behave as before.
- When a wrapper appears or disappears, ProseMirror rewrites the text nodes beside it and Chromium drops the spelling marks in them. After typing in a paragraph of up to about 1,000 characters Chromium rechecks that paragraph by itself. In every other case the editor asks for a full recheck (the 1.2.7 mechanism): at once after Ignore All, and one second after editing pauses otherwise (an ignored word typed in a longer paragraph, Undo, Replace). Chromium checks only the editable text that holds the caret, and only text that is displayed, so a recheck never starts while the editor is hidden (Settings, the Markdown source view), while the caret is outside it (the Find panel) or inside an element with spell checking off: it would clear every mark and bring none back. It starts when the editor is on screen and holds the caret.
- With no ignored words, the usual case, none of this runs. With them, the cost grows with the number of ignored occurrences: each wrapper adds an element and two text nodes, and after every key press Chromium walks the whole document's text and ProseMirror looks up the decorations of every paragraph. In a 2 MB document (248,000 words) a key press takes about 35 ms; with a word ignored that occurs 4,950 times, about 65 ms. A word that frequent belongs in the dictionary.

Version 1.3.3's red lines in long paragraphs. Chromium keeps its spelling marks with each piece of text in the page and rechecks by itself only around the caret: a whole paragraph of up to 1,024 characters, otherwise 512 characters either side. Two things made a longer paragraph lose the marks farther away, and each has its own cure:

- *Text replaced as a whole* (`src/lib/minimal-text-updates.ts`). When ProseMirror changes a piece of text it assigns the whole new string, and Chromium then drops every mark in that piece. Smart Typography does this for each curly apostrophe, quotation mark, dash and ellipsis; Undo and Replace do it too. Inside an editor that assignment now replaces only the stretch that differs, and Chromium keeps the marks before it and moves the ones after it along. Typing with Smart Typography and Undo of typing lose nothing anymore.
- *Text built anew* (`src/components/editor/QuietRecheck.ts`, `recheckSpellingQuietly` in `src/lib/spelling.ts`). Formatting a word, splitting or joining paragraphs, and Undo of those put part of a paragraph into new pieces of text, which have no marks. For these the editor asks for a whole-document check of a kind that does not blink. Chromium checks a whole document again by itself once the length of its text has changed by more than 1,024 characters since the last whole check, and that check replaces the marks piece by piece instead of clearing them first. The editor changes the length Chromium counts without touching the document: an invisible piece of filler at the end of the editor element (no-break spaces in a ProseMirror widget, of no size, not selectable, not read aloud, not part of the text, a copy or the saved file) is made 1,100 characters longer or shorter, and Chromium is nudged by switching spell checking on for an element that holds nothing. A lost red line is back about a second and a half after the change. The filler must not be clipped by a box of no size: Chromium leaves clipped text out of its count.
- The filler is an element at the end of the document, and two things about that needed care. *It is never empty* (one character when short). An empty element that cannot be edited is a place of its own for Chromium's caret: Ctrl+End put the caret behind it instead of at the end of the last line, and Chromium does not scroll to a caret there; the editor moved the caret to the right place a moment later, but scrolls only when that moment is shorter than a twentieth of a second, so in a 2 MB document that had just been opened the window stayed where it was. With text in the filler the caret passes it by: Ctrl+End, Ctrl+Shift+End and the arrow keys at the end of the document do what they do without it. *The last block is no longer the last child* of the editor element, and the stylesheet takes the bottom margin from the last child; without a rule of its own (`.prose > :has(+ [data-spelling-filler])` in `src/App.css`) every document was 13 pixels taller. Pictures of eighteen documents, each ending in a different kind of block, are the same in 1.3.2 and 1.3.3 to the pixel.
- The rechecks of 1.2.7 to 1.3.2 that switch spell checking off and on (after a paste, Replace, Ignore All, Clear Custom Dictionary and a return from the source view) are unchanged: their red lines still blink for about a second. Moving them to the quiet check is possible and was left for later.
- A blinking recheck and a quiet one can meet. The blinking kind goes over the document one second after it is asked for. A change made before that pass is covered by it, so no quiet check is asked for then (it would only make the blink longer); a change made after it gets its quiet check like any other. The editor cannot see when Chromium's pass runs, only that it cannot start earlier than a second after the switching, so the quiet check is skipped for changes made in the first 0.8 seconds and not later. (A first version skipped it for 1.5 seconds: Bold between 1.0 and 1.2 seconds after a paste then lost the red line after the word for good, 8 times of 9.)
- If the caret leaves the document within a second of a blinking recheck (for the Find box, say), Chromium's pass finds no caret and gives up, as in earlier versions. Chromium makes a pass of its own when the caret is in the document again, and that pass checks everything, because the document counts as unchecked. A trial of drawing frames after every caret movement, to make sure that pass gets its turn in a window that stands still, was taken out again: without it the red lines were back at one look three seconds after the return in 85 of 86 tries, with it in 16 of 16, and those numbers show no difference.

Version 1.3.3's Find (`src/lib/find-text.ts`, `src/lib/find-in-document.ts`) searches with a pattern built from the Find box: every character stands for itself, capital or small, except that a straight apostrophe or quotation mark also stands for the curly ones, exactly two hyphens also for an em dash, and three periods also for an ellipsis. These are the conversions of Smart Typography, read backward. It works one way only: a typeset character in the Find box finds itself and nothing else, which keeps an exact search possible and keeps an em dash from matching the hyphens of a table line or of code. In the formatted view a paragraph is searched as one text, so a phrase is found across a change of formatting. Find lists, highlights and steps through 500 matches at most and shows "1/500+" when there are more; Replace All takes every match, and changes each paragraph once, which keeps hundreds of thousands of matches from freezing the window. What Replace puts in is the text of the Replace box, converted by `convertTypography` as if typed at that place when Smart Typography is on, and left as typed in code (in the source view: wherever Smart Typography does not act while typing; `protectedMarkdownPlaces` answers that for many places in one reading of the text).

Version 1.3.3's Undo. Putting a document's text into its editor was the first step of the undo history, because TipTap's `setContent` is an ordinary change. Ctrl+Z in a document that had just been opened, or once more than there were edits, took the whole text out again; Ctrl+Y brought it back, but a save in between wrote an empty file. The load now carries `addToHistory: false`. Revert to Saved starts a new editor and so loads the same way. The return from the Markdown source view still is a step of its own in the history, as before: one Undo there changes nothing that can be seen, and the next ones take back earlier typing.

Version 1.3.3's pictures (`resolveImageUrl` in `src/lib/desktop.ts`, `desktop/shared-folders.cjs`). A picture address such as `//server/share/x.png` or `file://server/share/x.png` names a file in a shared folder on another computer, and when Windows is asked for such a file it signs in to that computer with the user's account. A document from someone else could point a picture at a computer set up to collect that. Such a picture now gets no address in the page, however the address is written (two slashes, backslashes, `file:` with a host, four or more slashes, percent signs), and the main process refuses any request for a file on another computer that is made all the same. The exception is the computer the document itself is on, and the one PicoMarQ runs from: a document in a shared folder shows its pictures. A drive letter that is mapped to a share is a path on this computer and works as before. Pictures on the web are still fetched when a document is opened. Nothing else in a document was found to ask another computer for a file: markup in a diagram's labels is shown as text, the math commands that fetch are switched off, other HTML is dropped, and a link is opened only on a click and only as a web or mail link. `tests/pictures-smoke.cjs` checks that too, which matters when the parts PicoMarQ is built from are next updated.

Version 1.3.2's Find highlights (`src/components/editor/SearchHighlight.ts`, `src/lib/search-matches.ts`) leave the document's text alone:

- Through 1.3.1 the matches were ProseMirror decorations: an element around every match. To put an element around part of a paragraph, ProseMirror splits the paragraph's text into pieces, and Chromium drops its spelling marks from text that is rewritten. So every paragraph with a match lost its red lines, and taking the elements away again when Find closed rewrote the text once more and brought nothing back.
- Now the matches are painted with the CSS Custom Highlight API. The page gives Chromium a list of ranges under a name (`search-match`, and `search-match-active` for the current match), and Chromium paints `::highlight(name)` behind them without any change to the elements or the text. The colors are the ones used before: the selection color, half transparent for the matches that are not the current one. The two rules are added from the module itself, because the stylesheet compiler does not know `::highlight()` and warns about it.
- The plugin keeps the matches as positions and maps them through every change of the document, so the highlights stay on their words while you type with Find open, as the decorations did. A match whose text is deleted disappears, and the others keep their places in Find's list. A range is made again only when its text was rewritten (it no longer reads the text it was made for), so typing with Find open costs what it did.
- Replace and Replace All put text in without Chromium seeing it typed, so they ask for the recheck of 1.2.7. The caret is in the Find panel at that moment, where a recheck would clear every red line and bring none back (see 1.3.1 above), so it runs when the caret returns to the document.
- A recheck is idle work for Chromium: about a second after spell checking is switched off and on, it checks the document piece by piece when the page has nothing else to do. In a window in which nothing moves (no typing, no mouse, and no blinking caret because text is selected) that work sometimes did not get its turn: in tests of 1.3.1, 19 of 48 rechecks made with text selected left every red line outside the caret's paragraph missing until the mouse moved. A trace showed that Chromium's whole-document check had not started, and two frames drawn by hand started it at once. `drawFrames` in `src/lib/spelling.ts` therefore keeps the window drawing frames for two seconds after a recheck is asked for, longer in a long document. This goes back to 1.2.7; it came to light in the Find test, where Undo leaves text selected.

`npm run test:equivalence` verifies that parsing, serialization, word counts, and highlighting match TipTap's stock implementations across a corpus of documents and thousands of random edits, and that every document in the corpus reads back as the same document after PicoMarQ writes it (it runs inside Electron and needs a graphical session or Xvfb like the desktop smoke test).

## Markdown escapes

TipTap's Markdown extension dropped the `escape` tokens that marked produces for backslashed punctuation, so an escaped character vanished when a file was opened, and its serializer wrote text verbatim, so punctuation typed in the formatted view could change meaning on the next open. Version 0.1.11 adds `src/components/editor/MarkdownEscape.ts`, a one-line token handler that keeps the escaped character, and `src/lib/markdown-escape.ts`, which escapes prose on output (characters that are syntax anywhere; what would start a heading, quote, list, or rule at the start of a line; a pipe inside a table cell; a closing `#` run at the end of a heading). `markdown-serialize.ts` applies it to text nodes outside code, joining adjacent text nodes first. The front-matter tokenizer no longer tells marked to cut paragraphs at every `---`, which used to split `a---b` across two lines. Smart typography in the source view leaves an escaped character and the pair it begins alone (`\--`, `\...`, `\"`). The clipboard's plain-text flavour is not escaped, since it is pasted as plain text into other programs.

## Build

Node 22 or newer, npm, and network access for package installation:

```sh
npm ci
node node_modules/electron/install.js
npm run build
npm start
```

`npm run build` compiles the renderer into `dist/`. Tailwind reads every text file in the folder when it compiles the stylesheet, and that includes the compiled program of the previous build in `dist/` and the patch files in `history`. With the released `dist/` in place the build reproduces it byte for byte. Started without a `dist/` folder, the first build gives a stylesheet about 12 kB smaller, without 95 rules for words that occur only in the compiled program (no element of the running program was found to use one); a second build gives the released stylesheet.

`npm run package:windows` makes `release/PicoMarQ-Windows-x64-1.3.4.zip` (named after the version in `package.json`), containing a `PicoMarQ` folder with `PicoMarQ.exe` and its runtime. It runs on Linux/macOS with `zip` and `unzip` installed and uses Electron's official Windows package for the version named in `package.json` (44.11.5): downloaded, or, when the download does not get through, fetched beforehand and named in `PICOMARQ_ELECTRON_ZIP`. Either way the file's SHA-256 must equal the one in `checksums.json` of the `electron` npm package, which `package-lock.json` pins. Every file of Electron's package goes into the PicoMarQ package unchanged, except that `electron.exe` becomes `PicoMarQ.exe` with the PicoMarQ name, version, and icon (the script verifies that executable code and data are preserved) and Electron's sample application is left out. `RELEASE-VALIDATION.txt` in the package records the three checksums. Building on Windows can use WSL, or copy `dist`, `desktop`, `app.ico`, and application package.json into Electron's `resources/app` directory. This is how 1.3.4 was made, because its engine is new. Releases that keep the engine were made another way, which leaves the runtime of the previous release untouched: after `npm ci && npm run build`, `python scripts/repack-windows-from-1.3.2.py /path/to/PicoMarQ-Windows-x64-1.3.2.zip` made `release/PicoMarQ-Windows-x64-1.3.3.zip` (the earlier `repack-windows-from-*.py` scripts made 1.2.4, 1.2.6, 1.2.7, 1.3.0, 1.3.1 and 1.3.2 the same way).

The icon is drawn in `scripts/build-icon.cjs`; `npm run build:icon` renders it with Playwright's Chromium into `app.ico` (16–256 px, PNG entries), `assets/app-icon.svg`, and the PNG copies (`assets/app-icon.png`, `app-icon.png`). `assets/ICON.md` has the design notes.

## Theme preset files (1.2.6, Restore Default Theme in 1.2.7)

Open **Settings > Saved Themes**. **Save Theme…** opens the standard Windows Save dialog and writes a versioned `.json` theme file. **Load Theme…** opens the standard Windows Open dialog and restores the selected theme immediately across open windows. Both dialogs start in the `Themes` directory alongside `PicoMarQ.exe`, which is created automatically; if that directory is not writable, the user's Documents folder is offered instead. You may navigate to any directory. PicoMarQ verifies format and settings before applying a theme. A theme that names an unavailable system font switches to the built-in Sans family, while keeping its size and other typography settings. Invalid files leave the existing preferences unchanged.

**Restore Default Theme…** asks for confirmation, then returns colors for Light and Dark, typography (font, size, bold weight, line height), and User Interface settings (page width, text zoom, icon size) to the defaults a new profile starts with. Light or Dark, Startup, Smart Typography, documents, and saved theme files are not changed. To keep the current look, use Save Theme first.

Appearance preferences remain stored in the local profile and survive restarts; Save Theme creates an additional copy that can be moved or shared. Theme file operations do not modify Markdown files. When updating the portable application, retain your `Themes` folder. Theme presets exclude the Startup setting and the Smart Typography switch.

**Build note:** The Saved Themes panel is a separate script, `public/theme-presets-ui.js`, which Vite copies into `dist/`. Since 1.2.7 the renderer in `dist/` is compiled from this source with `npm ci && npm run build` (see `VALIDATION.md`).
